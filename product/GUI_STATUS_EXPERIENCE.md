GUI 状态体验模型 GUI_STATUS_EXPERIENCE

本文档定义 GUI 的状态机。GUI 不直接读取上游组件内部状态，只依赖 Local Control Plane 暴露的 API。
每个状态包含：触发条件、用户看到什么、可执行操作。状态之间的迁移由 Control Plane 事件驱动，GUI 不自行推断。

--------------------------------

总原则

GUI 是 Control Plane 状态的视图，不是状态的所有者。
GUI 永远只通过 Control Plane API 获取状态和下发操作，不绕过 Control Plane 直连上游组件。
当 Control Plane 不可达时，GUI 进入降级展示，但不得伪造状态。

--------------------------------

一、未安装

触发：首次启动，Control Plane 报告本地无任何组件记录。
看到：欢迎页，十分钟安装引导入口，环境检测结果。
操作：开始安装、查看前置要求、退出。
迁移：安装首项成功后 -> 已安装未配置。

--------------------------------

二、已安装未配置

触发：组件已安装，但凭证或 Telegram 配置缺失。
看到：安装总览（版本、位置）、待配置项清单、每项的缺失原因。
操作：进入模型授权、进入 Telegram 配置、重装某组件、查看日志。
迁移：必要配置补齐且校验通过 -> 需要登录或正在启动。

--------------------------------

三、需要登录

触发：组件已配置，但某上游账号未登录或登录已过期。
看到：未登录项标黄、登录入口、过期时间。
操作：发起登录、刷新登录状态、跳过该项继续（标记为受限）。
迁移：登录成功 -> 正在启动；用户跳过 -> 部分能力异常。

--------------------------------

四、配置无效

触发：配置已存在，但格式错误、不一致或校验未通过。
看到：标红的具体配置项、错误原因、修复建议、一键诊断入口。
操作：重新填写该项、一键诊断、回滚到上一份可用配置。
迁移：修复并通过校验 -> 正在启动。

--------------------------------

五、正在启动

触发：Control Plane 正在拉起 Hermes、cc-connect 等组件，尚未全部就绪。
看到：逐项启动进度、当前卡在哪个组件、已就绪项。
操作：查看启动日志、取消启动。
迁移：全部就绪 -> 运行正常；某项失败 -> 启动失败；用户取消 -> 已停止。

--------------------------------

六、运行正常

触发：所有核心链路就绪，Control Plane 报告健康。
看到：三条链路状态绿灯、当前模型、当前渠道、最近活动。
操作：一键测试、查看日志、停止、重启、打开配置、发起任务。
迁移：某链路异常 -> 部分能力异常；有新版本 -> 更新可用；用户停止 -> 已停止。

--------------------------------

七、部分能力异常

触发：核心运行中，但个别 Agent、渠道或链路异常，不影响其余部分。
看到：异常项标红并注明环节、正常项保持绿灯、受影响功能置灰。
操作：对异常项一键诊断、重启该项、查看日志、继续使用正常部分。
迁移：异常恢复 -> 运行正常；异常扩大至核心 -> 启动失败或已停止。

--------------------------------

八、更新可用

触发：Control Plane 检测到某组件有新版本或新 Patch。
看到：可更新项清单、版本对比、更新风险提示、当前状态不中断。
操作：立即更新、延后、查看更新内容、选择回滚点后再更新。
迁移：用户暂不更新 -> 保持原状态；更新中 -> 正在启动。

--------------------------------

九、启动失败

触发：启动过程中某核心组件失败，无法进入运行正常。
看到：失败组件标红、失败原因、启动日志入口、可恢复操作。
操作：一键诊断、重试启动、回滚到上一可用版本、查看日志。
迁移：重试成功 -> 运行正常；用户放弃 -> 已停止。

--------------------------------

十、已停止

触发：用户主动停止，或启动被取消后停留。
看到：已停止总览、上次状态、停止原因、可恢复操作。
操作：启动、修改配置后再启动、查看日志、导出诊断包。
迁移：用户启动 -> 正在启动。

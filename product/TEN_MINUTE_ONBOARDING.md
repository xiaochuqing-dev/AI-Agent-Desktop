十分钟安装引导 TEN_MINUTE_ONBOARDING

本文档定义正式产品在基本干净的 Windows 电脑上的目标流程，不表示安装器、Control Plane 或 GUI 已实现。
目标是普通用户在十分钟左右完成环境检测、组件安装、模型或账号授权、首发 Channel 配置、启动、健康检查和首次真实链路测试。
全程不要求用户手工编辑配置、查找内部目录、设置全局环境变量或理解监听端口、计划任务和 Secret 注入。

一、共同规则

每一步都由 Operation 记录阶段、结果和恢复点。应用退出、网络中断或电脑重启后，从最后一个已确认检查点继续，不重复已经成功的外部副作用。
所有普通配置进入 ModelConfigurationProvider；Secret 直接进入 CredentialProvider，业务配置只保存 credential_ref。
官方登录材料由官方流程管理，本应用只启动入口并读取脱敏状态，不截取密码、OAuth token 或 Session。
每个配置 scope 只有一个 ManagementOwner。本应用、官方登录、CC Switch 和外部工具不能同时写同一字段。
每个失败都提供普通用户说明、可执行恢复动作和可展开的脱敏诊断。

二、第零步：准备

用户需要可联网的受支持 Windows 版本，并准备自己选择的模型账号或 API 凭据，以及首发 Channel 所需的 Bot 与会话资料。
缺少某项时只阻断依赖它的步骤，已经完成的步骤继续保留。
管理员权限不是启动应用的前提；只有确实需要系统修改的单个操作才通过受限 helper 请求 UAC。

三、第一步：环境检测，目标约 1 分钟

Control Plane 只读检测操作系统、磁盘、网络、已知组件、受支持运行时、端口和生命周期所有权。
成功：显示“环境已就绪”和每项版本。
缺失：说明可由应用安装还是需要用户处理，不展示内部路径。
端口冲突：安全选择其他端口或说明冲突来源，不默认终止未知进程。
状态无法确认：标记“待确认”并允许重新检测，不猜测为未安装或正常。

四、第二步：组件安装，目标约 4 分钟

应用只从已验证来源安装所需组件和当前兼容版本，安装前校验来源、版本和摘要。
成功：逐项显示版本和可用能力。
失败：区分网络、权限、磁盘、完整性和兼容性问题，只重试失败阶段。
中断：保留安装 journal；重开后先探测实际状态，再继续或回滚。
更新或修复：先建立回滚点，不把“下载完成”当成“安装可用”。

五、第三步：模型与账号，目标约 2 分钟

路线 A，官方登录，默认推荐：
Claude Code、Codex 等支持官方登录的组件打开官方入口。本应用只显示 required、authenticating、authenticated、expired 或 invalid，不接管官方凭据。

路线 B，自定义 API，由本应用管理：
用户选择模型与 endpoint，Secret 直接保存到安全后端。候选配置先做结构校验，经用户同意后再做最小连通验证；验证通过不等于已经激活，原子提交成功后才更新 revision。

路线 C，CC Switch，高级可选：
只有发现兼容版本且用户主动选择时显示。启用后相关 scope 的 Owner 为 cc_switch，本应用只读。CC Switch 不进入新手必选条件。

任何路线失败都保留上一份有效配置。切换路线必须经过备份、revision 检查和 ManagementOwner 两阶段交接，不能只切换一个界面选项。

六、第四步：首发 Channel 配置，目标约 2 分钟

用户在 GUI 表单中填写首发 Channel 所需资料。Bot Token 等 Secret 直接进入 CredentialProvider；Channel 配置只保存引用和通用 channel_id、conversation_id 等 Control Plane 标识。
Adapter 在内部完成平台专属 ID、Mention 和 Reply 映射，GUI 与通用 schema 不读取平台原始对象。
校验默认只检查格式、凭据可用性、目标会话权限和连接条件，不发送测试消息。
失败时说明是哪一个 Bot、会话或网络条件需要处理，不回显 Secret 或私人标识。

七、第五步：启动、健康与首次测试，目标约 1 分钟

Control Plane 按依赖顺序启动组件并显示 Operation 阶段。所有必需组件运行后先做无副作用健康检查。
正式产品随后由用户明确确认一次真实链路测试；界面应说明会向哪个已配置测试会话发送消息，并允许只测试选中的 Agent/Channel。
全部通过：标记首次引导完成并进入运行正常。
部分失败：保留正常能力，只标出失败链路、失败环节和恢复动作。
超时：显示“结果待确认”，先探测送达与实际状态，不自动重复发送。

当前第一个最小纵向切片只实现发现、状态、只读配置校验、受控生命周期、无副作用健康和脱敏诊断，不执行上述真实 Channel 消息测试。

八、十分钟外的日常流程

日常启动、停止、诊断、更新、回滚和迁移复用相同 Operation、状态和错误语义。
GUI 关闭后 Control Plane 与后台服务继续运行。
因网络或上游服务波动未在十分钟内完成时，产品保留全部已确认进度，不要求用户从头开始。

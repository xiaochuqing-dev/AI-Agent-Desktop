十分钟安装引导 TEN_MINUTE_ONBOARDING

本文档定义普通用户在基本干净的 Windows 电脑上，十分钟内完成首次可用所需的完整流程。
所有 Token、Chat ID、绝对路径在文档中用占位符表示，真实值由 GUI 写入本地受控 Secret 存储，不入仓库。
每一步必须给出诊断信息：成功显示什么、失败显示什么、失败后可执行什么。

--------------------------------

第零步：前置说明（约 0 分钟，不算入十分钟）

适用前提：Windows 10 及以上，可联网，用户有管理员权限或可接受 UAC 提权。
用户需要事先准备：三个 Telegram Bot 的 Token（Hermes Bot、Claude Code Bot、Codex Bot）、
一个 Telegram 群的 Chat ID、一个本人 Telegram User ID、所需的模型 API Key 或账号。
以上材料缺一时，GUI 在对应步骤会明确提示缺哪一项，不阻断已完成步骤。

--------------------------------

第一步：环境检测（约 1 分钟）

GUI 启动后先做只读环境检测，不修改系统。
检测项：操作系统版本、Python 运行时、Node 运行时、Git、磁盘剩余空间、所需端口是否空闲、计划任务权限。
诊断：
检测全部通过 -> 显示绿色清单，进入第二步。
某项缺失 -> 该项标红，给出"由本应用自动安装"或"需用户手动处理"的明确建议。
端口被占用 -> 显示占用进程名，提供"终止占用进程"或"改用其他端口"二选一。
权限不足 -> 提示需要管理员权限，给出"以管理员身份重启本应用"按钮。

--------------------------------

第二步：组件安装（约 4 分钟）

本应用按检测结果安装缺失组件，默认装到用户目录，不污染系统全局。
安装项：Hermes 运行时与 multiagent 插件、cc-connect 二进制（含当前 Patch 集）、Claude Code CLI、Codex CLI、必要依赖。
诊断：
全部安装成功 -> 逐项变绿，显示版本与安装位置，进入第三步。
某项安装失败 -> 标红该项，显示失败原因（网络、权限、磁盘、签名），提供"重试该项"和"查看日志"。
版本不符合最低要求 -> 标黄，提示升级，提供"由本应用升级"按钮。
安装中断 -> 已成功项保留进度，重开后从断点继续，不重复安装。

--------------------------------

第三步：模型或账号授权（约 2 分钟）

用户在 GUI 表单填入所需凭证，由本应用写入本地 Secret 存储，不落明文配置文件。
授权项：Hermes 所用模型 API Key、Claude Code 所需账号、Codex 所需账号。
诊断：
凭证格式校验通过 -> 显示已授权项，进入第四步。
格式错误 -> 标红具体字段，提示正确格式示例，不提交。
连通性校验失败 -> 标黄，显示失败原因（401、超时、网络），允许"暂存并继续"但标记为待验证。
用户跳过 -> 标灰该项，提示后续可在配置页补填，但首次测试会跳过依赖该凭证的链路。

--------------------------------

第四步：Telegram 配置（约 2 分钟）

用户在 GUI 表单填入三个 Bot Token、群 Chat ID、本人 User ID，由本应用代写 cc-connect 的 config.toml 和 Hermes 的 multiagent.yaml。
诊断：
三个 Token 均通过 getMe 校验 -> 显示对应 Bot 用户名，与 multiagent.yaml 中的 telegram_username 自动匹配校验。
Chat ID 与 User ID 格式校验通过 -> 显示已配置，进入第五步。
Bot 用户名与配置不一致 -> 标红，提示去 BotFather 核对，不允许进入下一步。
Token 失效 -> 标红，提示重新生成，提供"重新填写该 Token"入口。
代理需要 -> 检测到网络受限时，提示填写代理地址，校验可达性。

--------------------------------

第五步：首次测试（约 1 分钟）

GUI 一键发起端到端测试，覆盖三条真实链路。
测试项：Hermes 私聊响应、Claude Code 经 cc-connect 群聊响应、Codex 经 cc-connect 群聊响应、群内显式 @ 路由。
诊断：
全部通过 -> 显示绿色总览，标记安装完成，进入"运行正常"状态。
部分链路失败 -> 仅失败链路标红，其余正常，给出该链路的具体失败环节和修复建议。
全部失败 -> 标红，提示常见原因（端口、Token、Hook Bearer、计划任务未启动），提供"一键诊断"按钮。
超时未返回 -> 标黄，提示可能是首次冷启动，提供"重试一次"按钮。

--------------------------------

六、十分钟外的善后

十分钟目标只覆盖到首次测试通过。后续的更新、回滚、迁移、多 Agent 组合属于日常使用，见各自专门文档。
若十分钟内因网络或上游服务波动未完成，GUI 必须保留全部已完成步骤，不要求重来。

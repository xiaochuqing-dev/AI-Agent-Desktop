已交付事实

Control Plane v1 契约与 ADR-001..004 已冻结。control-plane/ 已存在基础运行代码，支持 loopback + Bearer、只读发现、ReadinessReport、结构化 Diagnostic、DryRunPlan、Operation、SSE、基础恢复和脱敏。内置 Windows System、Hermes、cc-connect、Claude Code、Codex、CC Switch、Telegram Config 共 7 个只读 Adapter。OpenAPI 外部引用通过带文件基准 URI 的维护脚本校验。找到配置或 Token 引用不会被当成健康证据，unknown 不会被自动报绿。

产品范围

产品定位是面向 Windows 开发者的 Telegram AI 编程团队安装、配置、管理、诊断与恢复中心。首发仅 Windows 10/11 与 Telegram，用户可见 Hermes Bot、Claude Code Bot、Codex Bot，目标是三个 Agent 各自私聊和群聊共六条链路。cc-connect 是 V1 核心桥梁。CC Switch 是推荐但非强制入口。采用 Integration First，不重写上游。

下一阶段准确名称

cc-connect 单组件真实安装纵向切片。

只允许实现以下闭环

用户显式确认；持久化且可审计的 Operation；幂等；可取消但不虚报外部工作已停止；安装前快照；来源、版本与摘要锁定；cc-connect 单组件安装；唯一 ManagementOwner；无副作用健康验证；失败回滚；卸载或恢复路径。

开始前先核对真实 Git、GitHub Actions、来源版本与 SHA256。安装必须使用隔离验收路径，不得把 Reference Baseline 当前运行服务当作试验环境。

禁止事项

不要同时安装其他组件，不要提前实现 Telegram 自动绑定或六链路真实 E2E，不要发送真实 Telegram 消息，不要开发正式 GUI，不要扩大 dual_agent 或 5 个 cc-connect Patch，不要重写 Hermes、cc-connect、Claude Code 或 Codex，不要开发通用 Bridge、Provider 管理器、DAG、工作流市场或新 Channel，不要读取或输出真实 Secret，不要在没有用户确认和回滚点时停止或重启现有服务。

状态与证据规则

安装、配置、认证、运行、健康和更新必须正交。可执行文件、配置文件、Token 引用、普通消息、命令、Topic 和 Session 隔离的证据不得互相替代。无法证明时返回 unknown，能力不足返回 unsupported。所有 Diagnostic 必须有稳定 code、用户说明、建议动作并保持脱敏。

完成标准以 05_NEXT_PHASE.md 为准。任何未实现能力必须明确标为 planned、unknown、experimental 或 unsupported。

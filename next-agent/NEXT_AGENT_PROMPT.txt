下一阶段准确名称：
单组件真实安装纵向切片——把 dry-run 安装计划升级为可确认、可审计、可取消、可回滚的真实安装。
优先候选：cc-connect（已有 patch+构建链+SHA256 校验，边界最清晰）。

开始编码前：
- 先读 reports/CONTROL_PLANE_READINESS_SLICE_COMPLETION_REPORT.md，了解已实现端点矩阵、DEFERRED 项与技术债
- 核对自然语言设计与机器契约，发现冲突时同时修正，不静默选择一方
- 为实现语言与框架、事务存储、Windows 后台宿主、CredentialBackend 形成 ADR（已由 ADR-001..004 冻结，沿用即可）
- 建立 Provider 契约测试、Operation 恢复测试、安全测试和 Reference Baseline 回归计划
- 再次确认 src/ 与 integrations/cc-connect/patches/ 是当前参考实现证据，不得被旧快照覆盖

第一个最小纵向切片只能包含：
- 本机组件与依赖发现
- 安装、配置、授权、运行、健康、更新状态展示
- 版本、Agent、Capability 展示
- 脱敏配置读取和只读校验
- 通过 shadow plan 与 controlled takeover 门禁后的启动、停止、重启
- 无副作用健康检查
- 统一脱敏日志、Operation、SSE 和用户可理解错误

实现顺序是先只读观测，再逐组件接管生命周期。能力不足返回 unsupported，状态无法证明返回 unknown。不要用现有脚本拼接出虚假的完整能力。

禁止：
- 直接修改当前真实运行环境、配置、凭据、计划任务、junction 或服务
- 重启当前服务或执行会产生真实消息的 Telegram E2E
- 扩大 dual_agent 或 5 个 cc-connect Patch
- 重写 Hermes、cc-connect、Claude Code 或 Codex
- 开始正式 PySide6 GUI 大开发
- 新 Channel、新 Runtime、复杂讨论、通用 DAG、第二套消息总线或插件市场
- 把设计端点、experimental 能力或尽力取消写成已实现/强取消

PySide6 + Qt Widgets + QSS 是正式 GUI 当前首选，但 GUI 与 Control Plane 必须独立，GUI 关闭后台继续；Control Plane、领域模型和 Provider 契约不得依赖该 GUI 技术栈。

遇到真正的 Git、SHA256、源码或事实冲突时，以实际文件和 Git 为准，停下报告，不猜测、不强推。

凭据管理边界需求文档

文档定位: 定义各类凭据的保存、使用、备份、迁移、恢复的安全边界。
本文档是需求契约，不含实现代码。所有真实凭据一律使用占位符，禁止硬编码真实值。

一、凭据范围

本应用涉及的凭据包括但不限于:
1. Telegram Bot Token，占位符 <TELEGRAM_BOT_TOKEN>。
2. 模型 API Key，占位符 <MODEL_API_KEY>。
3. OAuth Token，占位符 <OAUTH_TOKEN>。
4. Bearer Token（如 hook 鉴权），占位符 <CC_HOOK_BEARER_TOKEN>。
5. 其他密钥（如 webhook receiver secret），占位符 <RECEIVER_SECRET>。

二、核心原则

1. 凭据只使用占位符表达，绝不硬编码真实值。
2. 凭据不进 Git，不进普通日志，不进错误堆栈输出。
3. 凭据由统一的凭据管理保管，配置文件只引用占位符或环境变量名。
4. 凭据在内存中最短存活，使用后及时清理，不长期驻留明文。
5. 凭据传输只走 localhost 或加密通道，不通过 URL query 传递（用 Header 传递）。

三、保存

1. 凭据保存在独立凭据存储中，与业务配置分离。
2. 凭据存储文件不纳入版本控制（见 .gitignore）。
3. 凭据存储文件权限最小化，仅当前用户可读写。
4. 真实值通过环境变量注入运行时，配置文件只写占位符或环境变量名。
5. 示例配置（如 config.example.toml）只含占位符，不含任何真实值。

四、使用

1. 运行时从凭据存储或环境变量读取真实值，不硬编码。
2. 日志中凭据字段必须脱敏，只显示前后少量字符或完全遮蔽。
3. 错误信息和异常堆栈不得包含凭据明文。
4. 凭据不得出现在 webhook URL、relay 参数等会被记录的位置。
5. 通道鉴权用 Authorization Header 传递 Bearer，不放 URL query。

五、备份与迁移

1. 凭据可备份: 备份时整体加密，备份文件不含明文凭据。
2. 凭据可迁移: 安装或迁移时安全转移凭据到新位置。
3. 迁移过程中凭据不落盘明文，不经过不受控的中间存储。
4. 迁移完成后校验凭据完整性，确认目标可用后清理源端临时副本。
5. 备份与迁移操作只处理授权范围内的凭据，不越权读取。

六、恢复

1. 凭据可从备份恢复，恢复时校验备份完整性与来源可信。
2. 恢复后更新运行时引用，确认各组件能正确读取新凭据。
3. 恢复失败时不破坏现有凭据存储，回滚到恢复前状态。

七、安装与迁移时的安全转移

1. 安装器写入凭据时，从用户输入或环境读取，不写入源码。
2. 安装器写入后立即收紧文件权限，移除中间临时文件。
3. 跨机迁移时凭据通过加密通道传输，不通过明文文件中转。
4. 迁移涉及的绝对路径使用占位符（如 <PROJECT_ROOT>、<HERMES_HOME>），
   真实路径由安装器按实际位置写入，不写入公开仓库。

八、状态对照（凭据操作的结果状态）

1. 操作成功: 凭据保存、读取、迁移、恢复完成，返回脱敏确认。
2. 操作失败: 凭据无效、存储不可写、解密失败、来源不可信，分别提示，不泄露细节。
3. 输入异常: 凭据为空、格式错误、长度不足，分别提示。
4. 状态差异: 凭据已存在时重复写入、凭据已失效时尝试使用，提示当前状态。
5. 频率限制: 短时间内高频读取或校验凭据应限流，防止暴力探测。

九、不做的事

1. 不在源码、配置示例、文档中写入任何真实凭据值。
2. 不把凭据放入普通日志或错误堆栈。
3. 不通过 URL query 传递任何凭据。
4. 不假设环境里已存在凭据，安装与运行时显式校验凭据可用性。
